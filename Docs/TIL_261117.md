# 깃을 통한 프로젝트 관리

- 수업 내용 정리.

    1> 깃과 깃허브는 어떤 역할을 하는가?
    - [깃]은 소스 코드의 이력과 버전을 로컬 환경에서 기록하고 관리하는 분산 버전 관리 시스템입니다.
    - [깃허브]는 깃으로 기록한 프로젝트 이력을 원격으로 저장하고, 여러 개발자와 공유 및 협업할 수 있는 클라우드 플랫폼입니다.

    2> 깃을 올리는 과정 설명.
    1. 상태 확인: `git status`로 변경된 파일 확인
    2. 스테이징: `git add <파일명>` 또는 `git add .`로 커밋 대상 지정
    3. 커밋: `git commit -m "메시지"`로 로컬 저장소에 버전 기록 생성
    4. 푸시: `git push origin <브랜치명>`으로 원격 저장소(깃허브)에 업로드

    3> 로컬과 리모트의 차이점 / 이 사이에 파일의 흐름을 이해했는가
    - 로컬(Local): 내 컴퓨터 안의 개인 작업 공간이며, 인터넷 연결 없이도 버전을 기록할 수 있습니다.
    - 리모트(Remote): 깃허브 등 서버에 존재하는 원격 저장소이며, 팀원과의 공유 및 백업을 담당합니다.
    - 파일의 흐름: 작업 디렉토리 ➡️ 스테이지(`git add`) ➡️ 로컬 저장소(`git commit`) ➡️ 원격 저장소(`git push`)

- 누가 깃을 쓰는가?
  - 개발자, 디자이너, 기획자 등 버전 관리와 협업이 필요한 모든 IT 실무자가 사용합니다.

- 왜 쓰는가?
  - 코드가 잘못되었을 때 이전 상태로 안전하게 되돌리기 위해, 그리고 변경 이력을 투명하게 추적하기 위해 씁니다.

- 언제 쓰면 좋을까?
  - 프로젝트를 시작하는 첫 순간부터, 코드를 수정하고 기록이나 백업이 필요할 때마다 항상 사용합니다.

- 어디에서 활용되고 있을까?
  - 오픈소스 개발, 기업의 실무 프로젝트 협업, 개인 포트폴리오 관리 등 전 세계 개발 환경 전반에서 활용됩니다.
